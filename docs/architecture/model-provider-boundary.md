# 模型提供商与密钥边界

## 用户体验目标

用户在设置中填写自己的 API 密钥并配置可用模型。创建对局时，每个座位只能选择当前已正确配置且通过连通性检查的模型，也可以在未来选择真人玩家。

## 安全边界

- 密钥由用户填写，不写入源码、规则库、日志、回放或 Git。
- 前端不应在普通日志和错误提示中回显完整密钥。
- 每个提供商适配器只负责鉴权、请求、响应和错误归一化。
- 游戏规则不依赖任何厂商专有返回格式。
- “有密钥”不等于“模型可用”；开始游戏前还需检查模型配置与连接状态。

## 座位抽象

座位只引用一个玩家控制器：

- AI 控制器：提供商、模型和运行参数。
- 真人控制器：用户连接和输入通道。

角色身份与控制器相互独立。任何 AI 模型或真人都可以抽到任意合法角色，角色能力完全由规则引擎授予。

## 输出边界

模型输出分为两类：

- 公开发言：经过长度与安全校验后进入对局事件流。
- 结构化行动：由规则引擎校验阶段、目标和权限后执行。

内部推理、隐藏提示词和 API 原始响应不进入观战事件流。

# WFill 本地 AI 对局与观战网站设计

- 文档状态：待用户书面审核
- 设计日期：2026-08-22
- 依赖基线：`dce49f6` 六人无警长确定性规则引擎
- 视觉方向：A「寂静剧场」

## 1. 目标

本阶段把已经验证的规则引擎变成可在本地浏览器中实际游玩的 AI 狼人杀应用。用户可以配置学校提供的 OpenAI-Compatible 大模型网关，为六个座位选择任意可用文本模型，启动一局全 AI 六人狼人杀，并通过公开、跟随座位或上帝视角观看完整对局。

本阶段的完成标准不是“页面能展示几段聊天”，而是六个真实 API 玩家能够在确定性裁判约束下完成狼队交流、角色技能、公开发言、投票、平票 PK、遗言和胜负结算；刷新或重启后可以安全恢复，所有视角均不越权。

## 2. 范围

### 2.1 包含

- 一个或多个 OpenAI-Compatible 网关账户。
- 每个账户一枚独立凭据引用和若干可用模型。
- `/v1/models` 自动同步与手动添加模型 ID 两种路径。
- 模型连通性检查和健康状态。
- 六个 AI 座位独立选择账户与模型，允许重复选择同一模型。
- 固定六人无警长版型的创建、运行、暂停、单步、调速、恢复和回放。
- 公开、跟随座位、上帝三种观战投影。
- 版本化提示词、结构化行动、发言预算、重试和 Token 统计。
- 黑色为主的 A「寂静剧场」桌面浏览器界面。
- SQLite 本地存储、服务端事件流、浏览器端到端测试和真实网关冒烟测试。

### 2.2 不包含

- 真人玩家、多人联网房间或账户系统。
- 9 人、12 人、警长和新角色运行实现。
- 本地模型、多模态、语音、图片或思维链展示。
- Steam、桌面封装、云部署、公开匹配、排行榜和付费系统。
- Cloudflare Workers、Durable Objects、D1 或 Codex Sites 的实际部署与账户配置。
- Anthropic、Gemini 等非 OpenAI-Compatible 原生协议适配器。
- 复杂头像、音效、3D、重动画或其他不影响首局可玩的装饰。

## 3. 总体架构

继续采用模块化单体，新增四个工作区单元：

```text
apps/web
  React + Vite，只消费安全视图和应用命令

apps/server
  Fastify REST + SSE，组装服务并持有运行中对局

packages/application
  对局编排、玩家控制器、信息投影、提示词、失败策略

packages/persistence
  SQLite 仓储、审计日志、快照、模型配置和调用统计

packages/model-gateway
  OpenAI-Compatible 适配器、凭据引用、输出归一化
```

依赖保持单向：

```text
web → server contracts
server → application + persistence
application → game-engine + model-gateway + persistence ports
model-gateway → provider HTTP + credential vault port
persistence → SQLite
game-engine / rules-core → 不依赖上述任何层
```

前端不得引用 `GameState`、审计检查点或 API Key。服务端必须先生成安全投影，再通过 REST/SSE 发送给浏览器。

## 4. 模型账户与凭据

### 4.1 账户模型

一个模型账户包含：

- `accountId`：本地稳定 ID。
- `displayName`：例如“学校网关 Key 1”。
- `providerKind`：首版固定为 `openai-compatible`。
- `baseUrl`：网关地址，规范化后保存。
- `credentialRef`：凭据库引用，不是密钥。
- `models`：模型 ID、显示名、来源标签、启用状态和最近健康结果。

一枚 Key 可以授权多个模型；用户也可以创建多个账户。座位绑定 `accountId + modelId`，不直接绑定供应商品牌。房主配置页可以显示模型来源，进入对局后所有参与者只称呼座位号。

### 4.2 密钥边界

- API Key 由本地服务端接收后立即写入 `CredentialVault`，SQLite 只保存 `credentialRef`。
- Windows 首版使用当前用户作用域的系统凭据后端；测试使用内存实现。
- 前端提交后只得到“已配置”和末四位掩码，不能再次读取明文。
- 密钥不进入 Git、SQLite、事件、提示词、日志、回放、错误栈或模型调用统计。
- 删除账户时先阻止新调用，再删除凭据和非历史模型配置；历史对局仅保留当时的模型显示快照。

### 4.3 发现与健康检查

“同步模型”优先调用 OpenAI-Compatible `GET /v1/models`。若网关未实现、返回不兼容或 Key 只允许已知模型，用户可以手动输入模型 ID。健康检查使用极短文本请求验证鉴权、模型存在和基本文本输出，不把健康通过等同于结构化行动能力通过。

## 5. 模型网关

`ModelGateway` 对上层只暴露统一接口：

- `listModels(account)`
- `checkModel(account, modelId)`
- `generateSpeech(request)`
- `generateAction(request, schema)`
- `cancel(callId)`

统一响应包含文本或已验证行动、输入/输出 Token、延迟、结束原因和规范化错误。首版支持 OpenAI Chat Completions 风格；若网关支持 JSON Schema 则优先使用，否则要求 JSON 并在本地用 Zod 校验。

错误分类至少包括鉴权失败、模型不存在、额度不足、限流、超时、网络失败、格式错误、内容为空、主动取消和未知提供商错误。底层响应正文只在内存中用于解析，不作为普通日志持久化。

## 6. 对局编排器

每个运行中对局由单写者 `GameSessionRunner` 驱动，禁止两个任务并发提交同一局命令。一次循环为：

1. 从规则引擎读取当前合法动作快照。
2. 根据行动者和视角生成安全 `SeatView`。
3. 冻结 `expectedVersion` 和当前提示词输入。
4. 调用对应玩家控制器。
5. 校验响应格式、发言预算、目标和版本。
6. 向规则引擎提交命令。
7. 在同一持久化事务中写入领域事件、god-only 审计记录、最新快照和调用元数据。
8. 通过 SSE 推送新的安全视图和展示事件。

暂停只阻止开始下一次模型调用，不中断已经进入规则引擎的原子提交。停止或切换模型时可以取消在途 HTTP 请求；迟到响应因版本不匹配而被拒绝，不得进入对局。

自动模式连续选择下一行动者；单步模式每成功处理一个命令后暂停。展示速度只影响 UI 节奏，不进入规则时间或胜负逻辑。

## 7. 投影与观战权限

服务端投影器从真实状态和事件生成以下视图：

- `public`：公开发言、系统播报、公开投票、存活状态、死亡座位和结算。
- `seat:<n>`：在公开内容上增加该座位身份、技能资源、查验结果和依法可见的狼人队友/密聊。
- `god`：所有身份、真实死因、夜间行动、狼人密聊和技能资源。

观战视角只是不同的服务端订阅投影，不重新运行对局。任何视角都不包含 API Key、隐藏系统提示词、原始请求/响应、供应商品牌或模型思维链。

切换到更高权限视角在本地单用户首版无需登录，但必须显式选择；回放导出必须带视角标签，公开回放不能混入 god 数据。

## 8. 提示词与输出协议

每次模型调用按固定顺序组装：

1. 最高约束：模型是指定座位的玩家，以本局合法胜利为目标；不输出分析过程。
2. 版型规则摘要。
3. 私有角色卡、能力和剩余资源。
4. 该座位依法可见的结构化事实与历史文本。
5. 当前唯一任务和合法动作集合。
6. 发言要求或结构化 JSON 输出协议。

玩家文本被放在明确的不可信内容区，不能覆盖系统指令。自然语言中的投票或技能宣称不产生规则效果，只有结构化命令生效。

### 8.1 发言预算

- 普通发言：建议 80–180 个汉字，硬上限 220。
- PK 和遗言：硬上限 150。
- 狼队交流：硬上限 100，每狼每夜最多两次。
- 技能附带台词：硬上限 60。

先通过提示词与输出 Token 限制；超限时请求压缩一次，仍超限则在完整句子边界截断。系统只保存和展示最终公开文本。

### 8.2 失败降级

- JSON 解析失败：进行一次只修格式的低成本重试。
- 普通发言最终失败：记为跳过发言。
- 投票最终失败：转换为弃票。
- 可选技能最终失败：转换为不发动。
- 强制动作最终失败：暂停，允许重试或更换已配置模型。
- 网络、限流和暂时性错误：指数退避并最多重试两次。

所有自动降级均生成可回放的系统事件，不能静默改变对局。

## 9. 数据与恢复

SQLite 至少保存：

- 模型账户非敏感配置和模型目录。
- 对局元数据、规则快照和六个座位的模型显示快照。
- 领域事件、god-only 审计日志与周期状态快照。
- 模型调用用途、座位、模型、延迟、Token、重试和错误分类。

凭据不进入 SQLite。写入采用事务和单调事件序号。服务重启后，通过最近快照和后续审计日志恢复；恢复器必须校验同局、同规则版本、命令连续性和 `processedCommandIds` 精确前缀。恢复完成后重新生成视图，不重复执行已处理命令。

首版不承诺从纯公开事件重建真实状态；真实恢复使用 god-only 审计日志，公开回放只消费公开投影事件。

## 10. HTTP 与 SSE 边界

REST 负责配置和明确命令：

- 模型账户增删改、保存 Key、同步模型、健康检查。
- 创建对局、查询对局、开始、暂停、继续、单步、调整展示速度。
- 切换观战视角和读取历史回放。

SSE 负责单向推送：

- 安全投影快照。
- 新的系统播报和玩家发言。
- 座位状态、调用中/重试中/失败状态。
- 阶段、投票、结算和连接心跳。

客户端断线后携带最后事件序号重连；服务端补发可用事件或发送新的完整安全快照。首版没有需要 WebSocket 的真人双向实时输入。

## 11. 页面与交互

### 11.1 页面

1. 首页：新建对局、继续未完成对局、历史对局、模型管理。
2. 模型管理：账户、Base URL、写入 Key、模型同步、手动模型和健康状态。
3. 创建对局：固定六人版型，六席分别选择健康账户与模型。
4. 对局/回放：左右座位、中央信息舞台、视角和播放控制。

### 11.2 对局布局

- 左侧 01–03 号座位，右侧 04–06 号座位。
- 中央显示连续的系统播报与当前玩家发言，当前条目获得最高视觉层级。
- 顶部显示天数、昼夜、阶段、模式、速度和视角。
- 底部显示暂停、继续、单步；未来真人输入区保留组件边界但首版不渲染。
- 死亡、当前发言、投票、重试和依法可见身份只装饰座位卡。

### 11.3 A「寂静剧场」视觉规范

- 接近纯黑的主背景，中央舞台提高一个明度层级。
- 灰白为主要文字；低饱和紫色只用于当前行动和主按钮。
- 红色只表示死亡与错误；金色预留给未来警徽。
- 使用细边框和轻量阴影，不使用模型 Logo、玩家头像或大面积渐变。
- 状态动画 150–250ms，并尊重 `prefers-reduced-motion`。
- 1280×720 必须完整可操作；更窄屏幕优先保证中央内容并压缩座位卡。
- UI 只显示座位号，不在游戏内容区显示模型名称。

布局职责从首版固定。后续美化可以替换颜色、字体、材质和动画，不改变页面区域、数据来源或命令接口。

## 12. 测试策略

### 12.1 单元与契约测试

- OpenAI-Compatible 请求、响应、错误和模型列表归一化。
- 凭据引用不可回读明文，日志脱敏。
- 提示词层级、合法动作、视角信息和字符预算。
- 公开、跟随和 god 投影的正反权限矩阵。
- 编排器版本冻结、取消、重试、降级和单写者行为。
- SQLite 事务、恢复、重复命令和审计完整性。

### 12.2 集成测试

- 使用本地假 OpenAI-Compatible 服务完成两种阵营胜局。
- 六座位混合不同模型能力，包括格式错误、超时和限流。
- 暂停、单步、恢复、SSE 重连和视角切换。
- 任何公开响应均不含身份、死因、私聊、Key 或 god 审计字段。

### 12.3 浏览器验收

Playwright 覆盖模型配置、创建对局、完整对局、三种视角、失败提示、刷新恢复、结算和回放。人工浏览器检查至少覆盖 1280×720 与常见桌面尺寸，并确认中央内容可读、左右座位稳定、无横向溢出。

### 12.4 真实网关冒烟测试

用户在本机自行填写学校网关 Base URL 和 Key。测试只选择少量已授权文本模型，验证模型同步或手动登记、健康检查、六席开局和至少一局结算。测试报告记录模型 ID、成功率、延迟和 Token，不记录密钥或原始隐藏内容。

## 13. 验收标准

1. 能添加多个学校 OpenAI-Compatible 网关账户，凭据不进入 Git、SQLite、日志或浏览器持久化。
2. 能自动同步或手动登记模型，并只在创建对局时显示已启用且健康的文本模型。
3. 六个座位能任意选择模型并由真实 API 自动完成整局。
4. 狼聊、角色技能、公开发言、投票、PK、遗言和胜负全部经过规则引擎。
5. 公开、跟随座位和上帝视角通过权限反例测试，无信息越权。
6. 支持自动、暂停、继续、单步、展示调速、刷新恢复和历史回放。
7. 对局页面符合 A「寂静剧场」布局与视觉约束，在 1280×720 完整可操作。
8. 全量 Vitest、集成测试、Playwright 和构建检查通过。
9. README 提供本地启动、Base URL、Key、同步/手动模型、六席配置和开局步骤。
10. Codex 实际启动本地网站并用浏览器检查主要流程；不能用静态截图代替运行验证。

## 14. 已锁定的实现裁决

- 首版只实现 OpenAI-Compatible 协议；厂商品牌作为模型元数据，不进入规则逻辑。
- 一枚 Key 对应一个账户，可授权多个模型；允许多个账户和座位重复用同一模型。
- 模型列表发现失败时必须提供手动模型 ID 路径。
- 结构化动作与公开发言分离，模型没有裁判权限。
- 密钥使用本地凭据库，SQLite 只保存引用。
- 真实恢复使用 god-only 审计日志；公开事件只用于安全展示和公开回放。
- 视觉采用 A「寂静剧场」，黑色为主、克制紫色强调、固定三栏。
- 首版坚持本地单用户和全 AI 对局，不提前加入真人或公网系统。

## 15. 部署可移植性

首版只在本地 Node.js、浏览器和 SQLite 上运行，不为 Cloudflare 或 Codex Sites 增加实际部署任务。但模块边界必须保留以下迁移可能：

- HTTP 路由只依赖标准 Request/Response 语义，Fastify 适配位于应用层之外。
- `GameSessionRunner` 通过会话仓储和事件发布端口工作，不直接持有 SQLite 连接；未来可以映射为“每局一个 Durable Object”的单写者实例。
- 本地 SQLite 只实现仓储端口；未来 D1 或 Durable Object SQLite 可以提供云端实现。
- `CredentialVault` 是独立端口；本地使用当前用户凭据库，Cloudflare 可替换为 Worker Secrets/Secrets Store，Sites 可替换为其运行时秘密变量。
- 实时更新由内部 `GameUpdatePublisher` 抽象产生；本地适配为 SSE，未来可替换为 Durable Object WebSocket 或托管平台支持的推送机制。
- React 前端只依赖版本化 HTTP/SSE 协议，可作为静态资源部署到 Cloudflare 或 Codex Sites，而不引用本地文件路径或 Node 专有模块。

未来若开始公网部署，应单独设计身份认证、多人访问权限、滥用防护、配额、云端凭据所有权和费用边界；本规格不提前假定这些安全决策。
